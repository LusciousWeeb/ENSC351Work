Explanation

The bug:
In tradeArrays() (noworky.c, line 27), the loop variable is declared as
"unsigned int i". The loop is:

    for (i = size-1; i >= 0; i--)

Because i is unsigned, it can never be negative, so "i >= 0" is always
true and the loop never ends. After the iteration with i = 0, i-- wraps
around to 4294967295 (the largest 32-bit unsigned value). swapContent()
is then called with array1+i and array2+i, which point far past the end
of the 10-element arrays, causing the segmentation fault.

How I found it:
1. Ran noworky under gdbserver on the target and connected with
   gdb-multiarch from the host ("target remote 192.168.7.2:2001").
2. "continue" ran the program until it crashed with SIGSEGV in
   swapContent() at line 17, with invalid pointers d1/d2.
3. "bt" showed the call chain main() -> tradeArrays() -> swapContent(),
   so the bad pointers came from tradeArrays().
4. "up" moved to the tradeArrays() frame. "print i" showed
   i = 4294967295, while "print size" showed size = 10, so the index was
   far out of range.
5. "list" showed that i is declared "unsigned int" and the loop
   condition is "i >= 0", which explains the wrap-around.

The fix:
Change "unsigned int i;" to "int i;" in tradeArrays(). With a signed int,
i becomes -1 after the last iteration, "i >= 0" is false, and the loop
ends correctly.
