Explanation

The bug:
In tradeArrays() (noworky.c, line 27), the loop variable is declared as
"unsigned int i". The loop is:

    for (i = size-1; i >= 0; i--)

Because i is unsigned, it can never be negative, so the condition
"i >= 0" is always true and the loop never ends. After the iteration
with i = 0, the i-- makes i wrap around to 4294967295 (the largest
unsigned 32-bit value). The code then calls swapContent(array1+i,
array2+i) with that index, which points about 32 GB past the end of
the arrays. Writing there causes the segmentation fault.

How I found it:
1. Ran noworky under gdbserver on the target and connected with
   gdb-multiarch from the host. "continue" ran until the program
   crashed with SIGSEGV inside swapContent().
2. "bt" showed swapContent() was called from tradeArrays(), and the
   pointer arguments d1/d2 were invalid addresses far from the arrays.
3. Moving "up" to the tradeArrays() frame and running "print i" showed
   i = 4294967295, which is far larger than the array size of 10.
4. "list" showed i is declared unsigned int and the loop condition is
   i >= 0.
5. To confirm, I restarted, set "break tradeArrays", used "display i"
   and stepped with "next". i counted down 9, 8, ..., 1, 0 and then
   became 4294967295 instead of the loop ending, which confirms the
   unsigned wrap-around.

The fix:
Change "unsigned int i;" to "int i;" in tradeArrays(). With a signed
int, i becomes -1 after the last iteration, the condition i >= 0 is
false, and the loop ends correctly.

Note: compiling with -Wextra (which includes -Wtype-limits) would have
warned "comparison of unsigned expression >= 0 is always true".
